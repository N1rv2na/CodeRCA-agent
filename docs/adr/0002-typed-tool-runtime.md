# ADR-0002：使用结构化工具运行时且不实现 MCP

- 状态：Accepted
- 日期：2026-08-05

## 背景

仅将 Python 函数注册到字典不足以展示工具系统设计；完整远程服务化或 MCP 又不是两周 MVP 的必要条件。

## 决策

实现与传输协议解耦的 `ToolSpec` 和运行时，支持：

- JSON Schema 输入输出校验；
- 参数错误、权限拒绝、超时和执行失败分类；
- 每工具独立超时；
- 只读、代码执行和文件修改权限；
- 大结果截断与 artifact 引用；
- 结构化调用原因、耗时、状态和摘要。

第一版冻结七个工具，不实现 MCP，也不允许任意 Shell。工具默认不自动重试。

## 替代方案

- 简单函数注册：开发更快，但缺少权限、错误和审计语义。
- MCP：互操作性更强，但不解决本项目核心验证问题。
- 每个工具独立服务：隔离更强，但部署与故障面明显扩大。

## 后果

- 正面：工具行为可验证，便于未来增加 MCP 或其他适配器。
- 负面：需要维护 Schema、错误合同和权限测试；MVP 不具备跨进程协议互操作能力。
