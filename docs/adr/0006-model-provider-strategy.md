# ADR-0006：本地优先、云端兜底的模型策略

- 状态：Superseded by ADR-0009
- 日期：2026-08-05

## 背景

开发机器为 RTX 4060 Ti 8 GB、16 GB 内存。本地模型能降低开发调用成本，但可能无法同时满足长上下文、代码推理、结构化工具调用和延迟要求。ChatGPT Plus 也不能被视为稳定的应用 API 预算。

## 决策

CodeRCA 依赖最小 `ModelProvider` 接口，并通过独立 HTTP 推理服务调用模型。embedding 和 reranker 优先本地运行；诊断模型本地优先。

2026-08-08 前用三个代表任务验证本地模型。若除延迟外的质量门槛失败，则允许最终端到端评测使用云端模型。开发与测试保留 Fake、录制回放和本地后端，以控制成本。

LLM Judge 应与诊断模型使用不同模型家族，并由人工复核全部隐藏结果。

## 替代方案

- 全云端：质量和吞吐更稳定，但成本与外部依赖增加。
- 全本地且绝不兜底：费用低，但可能损害核心招聘证据。
- 直接将 Codex SDK 作为 Agent 后端：可使用订阅额度，但会模糊 CodeRCA 自身工作流和工具设计的归属。

## 后果

- 正面：开发成本受控，最终质量有退路，模型后端可替换。
- 负面：需要维护本地与云端的最小兼容层；具体模型和预算仍需实验冻结。
