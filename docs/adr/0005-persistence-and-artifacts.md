# ADR-0005：分离 SQLite 元数据与内容寻址 Artifact

- 状态：Superseded by ADR-0008
- 日期：2026-08-05

## 背景

诊断运行需要保存任务状态和事件，同时日志、代码、补丁、测试输出及模型响应可能很大。全部写入 SQLite 会使数据库膨胀并降低调试体验；完全基于文件又难以查询任务和事件。

## 决策

SQLite 保存任务、运行、结构化状态和追加事件。大对象保存在本地 artifact 目录，按内容哈希寻址，数据库只保存 artifact ID、媒体类型、大小和完整性信息。

单 worker 串行执行任务。服务重启时未完成任务标记为 `interrupted`，MVP 不自动恢复。

## 替代方案

- 全部写入 SQLite：事务简单，但大对象和重复内容管理较差。
- 只用文件：轻量，但查询、关联与一致性弱。
- PostgreSQL + 对象存储：适合多用户部署，但超出本地 MVP 范围。

## 后果

- 正面：结构化查询与大对象存储职责清楚，便于回放和去重。
- 负面：必须处理数据库记录与文件落盘的一致性、垃圾回收和完整性校验。
